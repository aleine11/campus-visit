## 一、项目整体架构

```
浏览器 (Vue3 前端)
   ↓ HTTP 请求 (JSON + JWT 令牌)
Controller 控制层   ← 接收请求、参数校验、返回 Result
   ↓
Service 业务层      ← 业务逻辑（预约审核、名额扣减、RAG 编排…）
   ↓
Mapper 数据访问层   ← MyBatis-Plus 自动生成 CRUD，不用写 SQL
   ↓
MySQL 8.0          ← 8 张业务表（用户/公告/场次/预约/知识库/会话/消息）

旁路组件（AI 咨询用）：
PDF/Word 文档 → PDFBox/POI 解析 → 文本分块 → BGE 模型转向量 → Milvus 存储
访客提问 → BGE 向量化 → Milvus 检索相似片段 → 拼提示词 → 阿里百炼 qwen-plus 生成回答
```

**为什么要分层？** 每层只干一件事，改哪层不影响别层（比如以后换数据库只动 Mapper 层），答辩也好讲清楚。

## 二、模块 0 知识点详解

### 2.1 MyBatis-Plus 实体注解（Entity 怎么"翻译"数据库表）

| 注解 | 作用 | 通俗解释 |
|------|------|---------|
| `@TableName("visitor_user")` | 指定表名 | 这个类对应数据库哪张表 |
| `@TableId(type = IdType.AUTO)` | 主键 + 自增 | id 由数据库自动分配 1、2、3… |
| `@TableLogic` | 逻辑删除 | "删除"只是把 deleted 字段改成 1，数据还在库里，查询时自动过滤掉 |
| `@Version` | 乐观锁版本号 | 防止多人并发修改把数据改乱（见 2.2） |
| `@TableField(fill = FieldFill.INSERT)` | 插入时自动填充 | 插入数据时 createTime 自动填当前时间，不用手动赋值 |
| `@TableField(fill = FieldFill.INSERT_UPDATE)` | 插入和更新都填充 | updateTime 每次改动自动刷新 |

> 项目里只有 3 张表用逻辑删除：公告、场次、知识库文档（这些数据有恢复价值）。
> 用户、预约、会话、消息表不用——预约删了就是删了，符合真实业务。

### 2.2 乐观锁防超卖（本项目的核心难点之一）

**场景**：某场次只剩 1 个名额，访客 A 和 B 同一秒提交预约。

```
A 的更新：UPDATE visit_session SET used_people = used_people + 2
          WHERE id = 1 AND version = 0     ← 影响行数 1，成功，version 变 1
B 的更新：UPDATE visit_session SET used_people = used_people + 2
          WHERE id = 1 AND version = 0     ← 影响行数 0，失败！version 已经不是 0 了
```

- MyBatis-Plus 的乐观锁插件自动帮我们加 `AND version = ?` 条件
- 业务代码发现更新影响 0 行 → 回滚事务 → 提示"名额已被抢完"
- **"乐观"的含义**：不加数据库锁，先假设没冲突，提交时才发现冲突（和"悲观锁"对比：悲观锁是一上来就锁住表，别人干等）

### 2.3 统一返回格式 Result + 状态码 ResultCode

**所有接口**都返回同一个 JSON 结构，前端只用写一套处理逻辑：

```json
{
  "code": 200,          // 200 成功；4xxxx 业务失败；5xxxx 系统错误
  "message": "success", // 提示信息
  "data": { ... },      // 业务数据，失败时是 null
  "timestamp": 1693100000000
}
```

状态码采用 **4xxxx 分段**（对标 architecture.md 第六章）：

| 分段 | 含义 | 例子 |
|------|------|------|
| 200 | 成功 | - |
| 40001~40099 | 参数/业务校验失败 | 40010 用户名或密码错误 |
| 40101 | 未登录 / token 过期 | 拦截器抛出 |
| 40301 | 无权限 | 访客访问管理员接口 |
| 40401 | 资源不存在 | 预约单不存在 |
| 50000 | 系统异常 | 兜底 |

**BusinessException（业务异常）**：业务代码里随时 `throw new BusinessException(ResultCode.RESERVATION_DUPLICATE)`，不用层层 return 错误，由 **GlobalExceptionHandler（全局异常处理器）** 统一捕获并转成上面的 JSON。

### 2.4 JWT 登录鉴权（前后端分离的标准方案）

**JWT = JSON Web Token**，本质是一串自带的"加密工牌"：

```
header.payload.signature
 头部.载荷.签名
```

- **payload（载荷）** 存：userId、role（visitor/admin）、isSuper、username、过期时间
- **signature（签名）** 用服务端密钥 secret 计算，客户端拿不到 secret → **无法伪造工牌**

**完整流程**：

```
1. 登录成功 → JwtUtil.generateToken() 生成 token → 返回给前端
2. 前端把 token 存 localStorage
3. 之后每次请求在请求头带上：Authorization: Bearer <token>
4. JwtAuthInterceptor（拦截器）在每个请求进来时验签：
   ├─ 有效 → 解析出用户信息 → 存进 UserContext（ThreadLocal）→ 放行
   └─ 无效/过期 → 抛 40101 异常 → 前端跳登录页
5. 请求结束 → UserContext.clear() 清理 ThreadLocal
```

### 2.5 BCrypt 密码加密（为什么不用 MD5？）

| 对比 | MD5 | BCrypt |
|------|-----|--------|
| 速度 | 极快（反被攻击者利用） | 慢（故意的，单次约 100ms） |
| 随机盐 | 无，同密码散列相同 | 有，同密码每次散列都不同 |
| 抗撞库 | 彩虹表可破解 | 几乎不可能 |

- 注册时：`BcryptUtil.encode("明文")` → `$2a$10$xxxx...`（60 位散列）存库
- 登录时：`BcryptUtil.matches("用户输入", "库里的散列")` → true/false
- **数据库永远不存明文密码**，就算库泄露了密码也安全

### 2.6 ThreadLocal 用户上下文（UserContext）

**问题**：请求里的用户信息存在请求头 token 里，Service 层怎么拿到当前用户？

**方案**：ThreadLocal = "每个线程自己的口袋"。
- Spring MVC 一个请求 = 一个线程
- 拦截器解析 token 后 `UserContext.set(用户信息)`
- 之后 Controller / Service 任何地方 `UserContext.getUserId()` 直接拿，不用层层传参

**⚠️ 必须在请求结束 clear()**：Tomcat 用线程池复用线程，不清理的话上一个用户的身份会"串"给下一个请求——重大安全漏洞！

### 2.7 注解式权限控制（@RequiresLogin / @RequiresRole）

在 Controller 方法上加注解即可获得鉴权能力，代码零侵入：

```java
@RequiresLogin                    // 只要登录
@GetMapping("/my-reservations")
public Result<?> myReservations() { ... }

@RequiresRole("admin")            // 要管理员角色（隐含需要登录）
@PostMapping("/admin/notice/save")
public Result<?> save(@RequestBody NoticeSaveDTO dto) { ... }

@RequiresRole(value = "admin", superOnly = true)   // 只要超管
```

拦截器自动读注解决定校验方式——**方法级注解优先于类级注解**。

### 2.8 数据库设计规范（database.md 精华）

| 规范 | 说明 |
|------|------|
| 字符集 utf8mb4 | 完整 UTF-8，支持 emoji 和生僻字 |
| 引擎 InnoDB | 支持事务（预约扣名额必须事务） |
| 主键统一 `id BIGINT AUTO_INCREMENT` | 与 MyBatis-Plus `id-type: auto` 对齐 |
| 不用物理外键，只建索引 | 一致性由应用层维护，方便迁移 |
| 联合索引最左前缀 | `idx_status_publish(status, publish_time)` 支撑"查已发布+按时间排序" |
| 冗余字段换性能 | 预约表冗余 real_name/phone，消息表冗余 visitor_id，避免 JOIN |
| 时间字段 | create_time/update_time 全表必备，自动填充 |

### 2.9 Git Flow 分支策略

```
main        ← 稳定版（只接收合并，不直接开发）
 ↑
develop     ← 开发主线（功能做完合到这里）
 ↑
feature/module-X  ← 每个模块一条分支，做完删除
```

## 三、IDEA 启动项目教程（手把手）

> 前提检查：电脑上装有 **JDK 17** 和 **MySQL 8.0**。
> 检查方法：`Win + R` 输入 `cmd` 回车，然后分别输入 `java -version` 和 `mysql --version`。
> 没装的话先告诉我，我带你装。

### 第 1 步：启动 MySQL 服务

1. `Win + R` → 输入 `services.msc` → 回车
2. 在服务列表找到 **MySQL80**（或 MySQL）
3. 右键 → **启动**（如果"启动"是灰的说明已在运行，跳过）
4. 建议：右键 → 属性 → 启动类型改为"自动"，以后开机自启

### 第 2 步：建库建表 + 灌种子数据（共 3 个 SQL 文件，按顺序执行）

用 IDEA 自带的数据库面板（不用装 Navicat）：

1. IDEA 右侧边栏点 **Database**（找不到就菜单 View → Tool Windows → Database）
2. 点 **+** → **Data Source** → **MySQL**
3. 第一次用会提示 *Download missing driver files* → 点 **Download**，等它下完
4. 填写：
   - Host：`localhost`　Port：`3306`
   - User：`root`　Password：**你的 MySQL 密码**
5. 点 **Test Connection** → 出现绿色对勾 → 点 **OK**
6. 按顺序打开下面 3 个文件，**每个文件顶部选择刚才的数据源，点绿色三角执行**：

| 顺序 | 文件 | 作用 |
|------|------|------|
| ① | `docs/init-database.sql` | 创建 campus_visit 数据库 |
| ② | `backend/src/main/resources/sql/schema.sql` | 创建 8 张表 |
| ③ | `backend/src/main/resources/sql/seed-data.sql` | 预置超管 + 公告 + 场次 |

7. 执行完在 Database 面板刷新（面板上的刷新图标），能看到 campus_visit 下 8 张表即成功

### 第 3 步：把你的 MySQL 密码填进配置文件

打开 `backend/src/main/resources/application-dev.yml`，把最后一行改成你的真实密码：

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://127.0.0.1:3306/campus_visit?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: "改成你的MySQL密码"   ← 只改这里
```

### 第 4 步：IDEA 打开项目并下载依赖

1. 菜单 **File → Open**
2. 选择文件夹 `campus-visit\backend`（选**里面有 pom.xml 的那层**）→ OK → **Trust Project**
3. IDEA 右下角会出现进度条自动下载 Maven 依赖，等它跑完（第一次约几分钟）
4. 如果没自动下载：右侧边栏点 **Maven** → 点左上角刷新图标（Reload All Maven Projects）

### 第 5 步：确认 JDK 17

1. 菜单 **File → Project Structure**（快捷键 Ctrl+Alt+Shift+S）
2. 左侧选 **Project**：
   - SDK：选 **17**（下拉没有就点 Add SDK → Download JDK → Version 选 17 → Download）
   - Language level：选 **17**

### 第 6 步：启动！

1. 双击打开 `CampusVisitApplication.java`
2. `main` 方法左边出现**绿色三角** → 点它 → **Run**
3. 控制台出现这个 ASCII 大框就是成功了：

```
╔══════════════════════════════════════════════════════╗
║   校园参观预约与智能咨询系统 启动成功                 ║
║   访问地址：http://localhost:8088/api                  ║
╚══════════════════════════════════════════════════════╝
```

4. 浏览器打开 `http://localhost:8088/api/` —— **显示 404 是正常的**！因为还没写 Controller（第一个业务模块"用户认证"才开始写接口）。404 恰恰证明服务器活着。

### 第 7 步：停止 / 重启

- 停止：控制台左侧**红色方块**
- 改了 Java 代码：点绿色**循环箭头**（Debug 重启）或手动重启

## 四、常见报错排查表

| 报错信息（关键词） | 原因 | 解决 |
|-------------------|------|------|
| `Access denied for user 'root'` | MySQL 密码不对 | 检查 application-dev.yml 的 password |
| `Unknown database 'campus_visit'` | 没执行第①个 SQL | 执行 docs/init-database.sql |
| `Table 'xxx' doesn't exist` | 没执行建表 SQL | 执行 schema.sql |
| `Communications link failure` | MySQL 服务没启动 | 回到第 1 步启动服务 |
| `Public Key Retrieval is not allowed` | JDBC 参数缺 | 配置里已加 `allowPublicKeyRetrieval=true`，检查 URL 没被改坏 |
| `Port 8088 was already in use` | 端口被占 | 关掉占端口的程序，或改 application.yml 的 port |
| `不支持发行版本 17` / `invalid target release` | JDK 版本低于 17 | 回到第 5 步配 JDK 17 |
| `Field 'xxx' doesn't have a default value` | 少执行了某个 SQL | 三个 SQL 按顺序全执行一遍 |
| 控制台中文乱码 | IDEA 编码问题 | File → Settings → Editor → File Encodings 全部 UTF-8 |
